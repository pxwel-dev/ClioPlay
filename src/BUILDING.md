# Building ClioPlay Global

For Windows installation of the included programs, use [WINDOWS.md](../WINDOWS.md)
and the root `Install.cmd` launcher. ARM compilation and the commands below
use Linux/WSL or macOS.

Run commands from this directory. The runtime and builder are independent
of sibling ClioPlay folders.

## ARM programs

Requires Python **3.12+**, Clang with the ARM backend, LLD ELF linker and an archive
tool capable of ARM ELF (LLVM `llvm-ar` on macOS). On macOS:

```sh
brew install python llvm lld
python3 tools/build_ui.py
cp build/clio040 build/cliospl build/clioa2dp clio843/
```

This builds `clio040`, `cliospl` and `clioa2dp` and copies them into
`clio843/`. If no UI/demo inputs changed, `--install` also installs them into
`clio843/`, where the clean installer reads them. Flags/compiler/input hashes and ELF checks are written to
`build/*.build.json`. Supply `--clang` / `--linker` if required.

The build also regenerates the splash icon's 8×8 coverage masks from
`tools/build_splash_icon.py`. This needs only Python's standard library; the head
unit composites the small masks directly without a supersampled framebuffer.

This `src/` directory is the canonical development tree inside
`CLIOPLAY-LATEST-VERSION/`. A successful `--install` build also refreshes the
parent folder’s clean-install publication. When UI sources have
changed, use the build/copy sequence above, then regenerate the demo with
`python3 tools/render_demo.py --sender-captures /path/to/private-browser-captures` before `python3 tools/refresh_latest.py`. A stale
demo deliberately prevents the automatic refresh from reporting success.
Documentation/packaging changes need `python3 tools/refresh_latest.py`; use
`python3 tools/refresh_latest.py --check` to verify the maintained delivery against
the current sources and installed programs. The exporter verifies publication integrity and preserves unrelated local additions;
the Git-payload check rejects additions that are not ignored or managed.

The first Unicode-engine build automatically fetches pinned, SHA-256 checked
Debian armel development **headers** into `build/cross-sysroot`. No Debian target
libc, libstdc++ or newer-CPU libgcc is linked. Arithmetic helpers are compiled from
vendored LLVM compiler-rt for ARM7TDMI. HarfBuzz and SheenBidi are vendored too.

Executables are freestanding static ARMv4T ELF32, EABI5 soft float, legacy Linux
OABI syscalls, image base 0x10000 and 64 KiB segment alignment. Build checks reject
dynamic loaders, missing entry points and unresolved symbols. The main executable
has about 10.1 MiB BSS, including the bounded 2 MiB shaping arena and existing map/
route caches. Native font tables are mapped on demand; glyph bitmaps stay on the
card, with a bounded RAM cache. Actual total memory/performance needs hardware
measurement. `--no-map-antialias` is a build-time rendering fallback.

Thin-road coverage is generated by `tools/build_thin_coverage.py` during the ARM
build. The minor-road class uses Gaussian reconstruction (sigma 0.55 pixels,
nominal width 1.2 pixels); other one-pixel strokes retain pixel-area coverage.
Body/cap lookup tables contain prequantised five-bit mask values. No floating
point, extra framebuffer or image-wide blur runs on the device.
`tests/map-antialias.c` checks independent pixel-area/kernel integration,
subpixel phases, slopes between lookup rows, caps, clipping and subdivision. To capture
matching before/after native framebuffers (Pillow required), preserve a complete
pre-change `clio843/src/` tree outside the publication, then run:

```sh
python3 tools/verify_minor_road_aa.py --maps /path/to/maps \
  --before-source /tmp/before-src/clio040.c --out /tmp/minor-road-aa
```

Captures and host timing reports stay outside the publication. The output uses
the production RGB565 framebuffer; magnified crops use nearest-pixel scaling.


## Navigation and optional font maintenance

```sh
python3 navigation-builder/build_navigation.py
```

This asks for the PBF first and guides region confirmation. Full requirements,
unattended options and camera imports are in
[navigation-builder/README.md](navigation-builder/README.md). Normal builds copy
the bundled, checksum-verified `data/global-fonts.cpf`; no font download or rasterizer
is needed. To regenerate it as a maintainer, install `freetype-py==2.5.1` and
`fonttools==4.60.1` plus a host FreeType library, then run:

```sh
python3 navigation-builder/tools/build_fonts.py --out navigation-builder/data/global-fonts.cpf --cache build/font-cache
```

Font upstream URLs are recorded in the generated report. Retain the resulting
`font-notices.json`, OFL licence and source manifest with the pack.

## Verification

A host C/C++ compiler is required. The framebuffer gallery needs Pillow.
The builder's `.venv` can run `verify_global.py` after its first dependency setup.

```sh
python3 tools/verify_unicode.py
python3 tools/verify_text_cache.py
python3 tools/verify_locales.py
python3 tools/verify_keyboard.py
python3 tools/verify_atlas_viewport.py --maps navigation-output
python3 tools/verify_atlas_qad7.py --maps navigation-output
python3 tools/verify_splash.py
navigation-builder/.venv/bin/python tools/verify_global.py
python3 tools/verify.py --maps /path/to/existing/UK/clio843/maps
```

`verify_unicode.py` links the production shaping engine and tests the actual
2 MiB allocator under host UBSan. It renders 17 native-script examples plus the
Trip screen; checks mixed bidirectional text, native phone handoff/persistence,
old saved-place migration and UTF‑8-safe rename/delete. These are rendered pixels,
not desktop browser text overlays.

`verify_global.py` builds clearly synthetic metric/imperial PBF fixtures through
the complete pipeline, compares routing against reference queries, exercises
country switching, limits, camera/GPS/average-zone behaviour and installation.
`--real-bundles` additionally uses locally prepared `build/paris` and `build/madrid`
sample bundles. These sample inputs are optional and not part of a source build.
`--cache PATH` reuses an existing coastline cache.

`tools/render_demo.py` regenerates the concise dark-led framebuffer showcase in
`docs/demo/`, with actual remote inputs and brief Day/Auto examples. It needs
Pillow, FFmpeg (or imageio-ffmpeg), a UK map/atlas covering Newcastle, and
external browser captures passed with `--sender-captures PATH`. Those captures
come from the separately maintained private companion project; no website
source or capture tooling is shipped here. The existing full showcase is kept
unchanged, including its phone section. Raw framebuffers,
compositions and host executables stay temporary; the publication contains only
the movie, poster, a short looping README preview, player, README and provenance
manifest. `tools/build_readme_preview.py` extracts that preview from the verified
movie; full demo generation calls it automatically. Refresh after the new
movie is complete; checks reject a movie captured from different native sources.

`verify_keyboard.py` checks all 18 independent language layouts, capital input,
accented/native names, connected remote focus paths, saved choices, soft-key
editing, character bounds, Pinyin candidates and all 11,172 modern Hangul
syllables. Its 78 Day/Night framebuffer captures and test settings stay temporary.
`verify_atlas_viewport.py` reproduces device boot ordering against a real UK
atlas covering Newcastle: maps open before GPS, then saved/live fixes and Explore
move beyond the first child pack. It checks every installed core and shared edge,
Day/Night zooms, genuine outside coverage and single-pack edge tolerance. It
uses existing map data read-only and keeps captures temporary.

`verify_atlas_qad7.py` uses the existing UK atlas covering Newcastle to check
mapped and forced-paged QAD7 with a minimum 1 MiB query arena, every regional
index namespace, exact regional route cost, endpoint-cache reset and local suffix
repair. It executes Newcastle–London against the existing UK fixture and checks
route cost/distance, shared work counts and production scheduling, rather than
using a desktop timer as evidence of acceptable 400 MHz performance.
`verify_atlas_destination.py` builds directed synthetic graphs to check unreachable
nearest-road fallback and first-candidate preference through another portal.
Host timings are comparative;
actual head-unit routing/rerouting timing and memory still need a vehicle trial.

Keyboard layouts are baked from `locales/keyboards.json`; normal builds use the
bundled Unicode Pinyin table and need no new SD-card data. See
[locales/README.md](locales/README.md) for input methods and limitations.

`verify.py` exercises the legacy UK pack with the real renderer/key handler,
including smooth routes, polygon holes, remote screens/animations and 72 bridge
views. Its historical `--compare` mode requires an optional old archive and is not
part of Global validation. No test modifies the supplied source navigation packs.

Publish the contents of the parent `CLIOPLAY-LATEST-VERSION/` folder as the
repository root. Run `python3 tools/refresh_latest.py` and
`python3 tools/verify_publication.py` first. Current programs, default bootstrap,
legacy helper recovery references and available BlueZ sources are included;
firmware, generated maps, caches and personal data stay local.

## Global follow-through checks

```sh
navigation-builder/.venv/bin/python tests/test_routing_policy.py
navigation-builder/.venv/bin/python tests/test_cameras.py
navigation-builder/.venv/bin/python tools/verify_atlas.py
navigation-builder/.venv/bin/python tools/verify_atlas_chain.py
navigation-builder/.venv/bin/python tools/verify_atlas_context.py
navigation-builder/.venv/bin/python tools/verify_atlas_destination.py
python3 tools/verify_border.py
navigation-builder/.venv/bin/python tools/verify_real_atlas.py
python3 tools/prepare_card.py /tmp/clioplay-clean-runtime
navigation-builder/.venv/bin/python tools/verify_install.py --prepared-runtime /tmp/clioplay-clean-runtime
```

The border checks require locally prepared real France/Spain extracts under
`build/real-border/`; they are validation inputs, not required source-build assets.
`verify_atlas.py` builds its own small overlapping restriction fixture from scratch.
Clock, roundabout and PCM cue C tests run under host UBSan. `build_ui.py` regenerates
interface translations before compiling; edit the locale JSON dictionaries to maintain them. The language list and
contribution workflow are in [locales/README.md](locales/README.md).
Hardware trial and evidence collection are documented in `docs/next-release/`.

`verify_splash.py` captures both boot themes from the production C framebuffer,
checks theme/brightness behaviour and icon compositing under UBSan, and writes
previews to `docs/next-release/splash-antialias/`. Its optional before captures
are historical reference data; they are not needed to build the splash.

## Automatic Navcore download

The clean-card installer downloads the official 8.843 CAB from TomTom, verifies
its pinned SHA-256 and reuses a verified cached copy on subsequent runs. If the
download fails, restore the internet connection and rerun the installer.
Only `ttsystem` and `vehicledaemon` are extracted from the CAB. AUX initialization
is embedded in the custom `ttn` startup script, so `PNDNavigator` is not installed.
The custom `focusd` and other
project helpers are included separately; see [source status](docs/source-status.md).
